# thread-weaving

Four inventories in, one fabric out.

## What a thread is

A thread is a line through ALL FOUR dimensions (or honestly fewer,
stated): a sci-fi concept that a proverb compresses, that a protocol
operationalises, that a spell seals. Example shape:

> moving ceiling R(t) (F) → "the ceiling moves; the floor is proven"
> (P) → GR-7 in-passage conditioning (R) → T∫ tracer glyph (S)

## Procedure

1. Read the four sweeps. Build the candidate threads from their
   `threads:` cross-references; confirm or cut each (?) guess against
   the anchors — a thread inherits the WEAKEST evidence of its links.
2. Write each confirmed thread as a section: the four (or fewer) beads
   named, the anchors carried over, one paragraph of weave (poetic
   register), and its **casting-forward direction** — stated as a
   choosable act: a paper, an instrument, a ceremony, a post.
3. Orphans matter: items no thread claims go in an "unwoven" table at
   the end. An unwoven proverb is a key without a lock — future signal,
   not failure.
4. Contradictions escalate, never resolve (GR-10 reaches this lane):
   if two dimensions disagree about what a symbol means, the weave
   RECORDS the disagreement as its own thread.

## Output

`overlays/WEAVE.md`: frontmatter (date, run id, sweep inputs, thread
count, unwoven count) · threads, strongest evidence first · the
casting-forward list gathered at the end as a single actionable table
for the first person · the unwoven table.

## The test of a good weave

The first person can read ONLY the casting-forward table and know what
the poetry wants next; a sceptic can read any thread and walk every
anchor back to the formal corpus without finding an added claim.
