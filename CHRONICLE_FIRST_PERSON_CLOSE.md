## The Four Bodies Update Pattern

The Four Bodies model from Act XXXI provides a template for understanding how each document type relates to the suite:

```
Sun (generation)     ──────────     Earth (proliferation)
   │                                      │
   │ core documents                  │ reference documents
   │ (immediate update)              │ (secondary update)
   │                                      │
   ▼                                      ▼
Moon (reflection)    ────gap────    Human (connection)
   │                                      │
   │ archive documents               │ external artifacts
   │ (historical record)             │ (blog, talks, etc.)
```

- **Sun-type documents** (grimoires) generate the content
- **Earth-type documents** (READMEs, whitepapers) proliferate understanding
- **Moon-type documents** (archives) reflect historical state
- **Human-type documents** (external content) connect to the world

The update flows outward from Sun to Moon, with Earth accelerating propagation.

## The Amnesia Itself as Method

There is a deeper principle here. Act XXXI teaches that **amnesia is the protocol** — that forgetting the derivation enables cleaner service.

Applied to documentation strategy:

1. **The grimoire forgets its draft history.** Each version presents itself as complete, not as revision. The edit logs exist in git, but the document reads as authoritative.

2. **The reference documents forget the grimoire's chronology.** They extract principles without requiring readers to traverse thirty-one acts. The whitepaper can state "the Ur-Swordsman is the Moon" without requiring the reader to follow how that insight emerged.

3. **The external artifacts forget the internal structure.** A blog post can present the Four Bodies model as a self-contained concept. The reader need not know about Acts I-XXX.

This is not hiding history — history lives in the archive ring. This is **enabling clean service** — each document serving its audience without cognitive overhead from derivation.
